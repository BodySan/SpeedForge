# Что проверено по истории Python-тестера

Предоставленный владельцем текст описывает прошлые дефекты DiagForge. Это историческая справка; результаты Python-версии не считаются доказательством работоспособности SpeedForge.

В текущем коде проверены следующие случаи:

| Прошлая проблема | Поведение SpeedForge |
|---|---|
| Процесс завершился с нулём байт | Результат «Нет данных», даже при успешном коде завершения |
| Очень низкая, но ненулевая скорость | Сохраняется без произвольного минимального порога; пример 0,026 Мбит/с включён в регрессионный набор |
| Неполный `--bidir` | Требуются скорость и принятые байты обоих направлений; основной режим проверяет направления последовательно |
| `-Z` не поддерживается Windows-сборкой | Этот параметр не используется |
| Порт открыт, но передача не начинается | Отдельный срок начала передачи; пробное TCP-соединение перед iPerf не используется |
| После остановки остаётся процесс | Остановка дерева процессов и подтверждение выхода с ограниченным ожиданием; проверяются реальные PID при таймауте и отмене |
| Автоматическое переключение города | Повторяются только опубликованные порты выбранного сервера |
| UDP TX выдан за скорость приёмника | Локальный TX показан отдельно; отсутствие отчёта сервера не становится нулевыми потерями или успешным приёмом |
| Синтетические проверки не повторили сбой Windows | Проверяются встроенные Windows-клиенты, локальные сетевые сценарии, реальные публичные серверы и интерфейс переносимого exe |

Параметры и время всех попыток сохраняются в локальном debug. Сырые сетевые журналы могут содержать IP-адреса клиента и не входят в открытые исходники или обезличенный отчёт проверки.

Исторические таймауты Python не перенесены автоматически: текущие сроки проверены отдельно для начала передачи, самой нагрузки и ожидания отчёта. Подробнее — [TIMINGS.md](TIMINGS.md).
