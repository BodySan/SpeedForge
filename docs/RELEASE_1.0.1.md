# SpeedForge 1.0.1

Исправления измерений и истории, особенно для профилей Билайна.

- В истории видны направление и название каждого профиля: например, `5(100)` или `20(1000)`. Вместо одинаковых `Partial` и `Timeout` показана причина: нет отчёта сервера, пришла только часть отчётов или истекло время ожидания.
- Прогон Билайна стал короче: по умолчанию 3 секунды на профиль, задержка до и после нагрузки измеряется один раз на весь прогон. Для исходной длительности можно указать 10 секунд.
- Исправлена совместимость со старым сервером iPerf2: встроен исходный клиент 2.0.8. Если сервер обновлён, программа проверяет современный клиент и использует подтверждённый вариант для остальных профилей.
- Параметры всех восьми профилей сохранены. Скорость определяется по фактическому приёму; привязки к тарифу 100 Мбит/с нет.
- Исправлен график iPerf3 UDP: локальная скорость отправки больше не появляется как принятая сервером скорость.
- Следующее направление сначала использует уже подтверждённый порт. На перебор дополнительных портов выделяется отдельное время.
- Для неполных отчётов iPerf2 указано, сколько потоков подтвердил сервер. Зависший измеритель останавливается; доступная статистика сохраняется.
- Ручная проверка загрузки на Билайне оставляет непроверенную отдачу в состоянии «Не проверено».

Все профили отдельно пройдены через консоль с исходным и встроенным iPerf2. Подробности — в [описании профилей](BEELINE_PROFILES.md). Проверены все 65 записей каталога и отдельно все 60 iPerf3-серверов в UDP. [Итоги подключений](SERVER_CHECKS_1.0.1.md).

Для запуска достаточно `SpeedForge.exe`. Установка .NET и отдельных измерителей не требуется.


Проверки выпуска: 100 регрессионных, 31 сценарий песочницы и 33 проверки интерфейса — 164 пройдены, ошибок нет. Ещё 18 сохранённых консольных отчётов проверены отдельно. [Сводка](QA_1.0.1.json).
