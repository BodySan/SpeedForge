# Проверка Билайна через iPerf2

В исходном архиве `Iperf speedcheck.gldn.net.zip` один сервер — `speedcheck.gldn.net:5001` — и восемь bat-файлов. Их параметры перенесены в приложение:

| Профиль | Потоки | Нагрузка на каждый поток |
|---|---:|---:|
| 1(100) | 1 | 100 Мбит/с |
| 5(100) | 5 | 100 Мбит/с |
| 10(100) | 10 | 100 Мбит/с |
| 20(100) | 20 | 100 Мбит/с |
| 1(1000) | 1 | 1000 Мбит/с |
| 5(1000) | 5 | 1000 Мбит/с |
| 10(1000) | 10 | 1000 Мбит/с |
| 20(1000) | 20 | 1000 Мбит/с |

Например, файл `iperf_5(100).bat` запускает `iperf.exe -c speedcheck.gldn.net -u -t 10 -i 1 -b 100M -P 5`. В iPerf2 `-P` задаёт число потоков, а `-b` — нагрузку каждого из них. Это параметры отправки, а не обещанная скорость тарифа.

Одна кнопка проходит все профили по очереди и затем отдельно проверяет загрузку на ПК. В 1.0.1 быстрый прогон использует 3 секунды на профиль. Если нужны исходные 10 секунд, измените длительность в параметрах. Задержка до и после нагрузки измеряется вокруг всего прогона, поэтому не добавляет по четыре секунды к каждому профилю.

При лимите 0 используются исходные значения нагрузки. Пользовательский общий лимит делится между потоками. Фиксированного ограничения до 100 Мбит/с нет.

## Как читать результат

В UDP компьютер может отправлять пакеты быстрее, чем канал способен доставить их серверу. Поэтому итог берётся из **Server Report** — отчёта принимающей стороны. Из подтверждённых полных профилей в главной карточке показывается лучший результат.

Если отчёта нет, скорость неизвестна: программа показывает прочерк и «Нет отчёта сервера». Локальная статистика отправки остаётся в отладке. Если пришёл отчёт только для одного из пяти потоков, скорость относится к этому потоку; запись помечается как неполная и не становится итогом всего профиля.

## Что проверено для 1.0.1

Все восемь команд с исходными нагрузками и длительностью 10 секунд выполнены через консоль. Сравнение выявило несовместимость отчётов: клиенты 2.2.1/2.2.2 неверно прочитали ответ старого сервера 2.0.8. Режим совместимости этого не исправил. Поэтому исходный iPerf2 2.0.8 встроен в приложение; ошибочные отчёты современных клиентов отклоняются.

На первом профиле программа проверяет совместимость. Если старый клиент не получает корректный отчёт, пробует встроенный 2.2.2. Подтверждённый вариант используется для остальных профилей. Это позволяет работать и с обновлённым сервером. Проверки обеих версий сохраняются в одном журнале профиля.

Старый Windows-сервер в прямых многопоточных запусках вернул отчёт только одного потока, а один клиент завис. В приложении ожидание ограничено. Для проверки всех потоков в автоматической песочнице используются отдельные порты настоящих серверов iPerf2 2.0.8: UDP-пакеты и отчёты передаются без изменения. Все восемь профилей с исходными нагрузками по 10 секунд подтвердили приём. Старый сервер не поддерживает современный обратный режим; проверка загрузки завершается без выдуманной скорости.

Отдельно проверены каналы разной ёмкости, отсутствие отчёта, обратная передача, отмена и неполные результаты. Публичная доступность Билайна проверяется отдельно: успешная локальная проверка не означает, что публичный сервер отвечает с любого подключения.

Описание флагов: [документация iPerf2](https://iperf2.sourceforge.io/iperf-manpage.html).
